1 Qual o papel da anotação @Path("/books") na classe CatalogResource?JAX-RS
  • A Define a URI base sob a qual os métodos do recurso ficam expostos.
  • B Define o verbo HTTP aceito pelo recurso.
  • C Registra um cliente REST para consumir outro serviço.
  • D Define o formato de serialização (JSON/XML) das respostas.
2 Por que Book foi implementado como record em vez de uma classe tradicional?Modelo
public record Book(Long id, String title, String author, boolean loaned) { }
  • A Records geram automaticamente construtor, getters, equals/hashCode e toString, reduzindo código repetitivo.
  • B Records permitem herança múltipla de outras classes.
  • C Records são obrigatórios em qualquer classe anotada com @Path.
  • D Records substituem a necessidade das anotações do JAX-RS.

7 O que acontece em newLoan quando bookCatalog.getBook(id) lança WebApplicationException (livro inexistente)?Tratamento de erro
try { book = bookCatalog.getBook(request.bookId()); } catch (WebApplicationException e) { return Response.status(Response.Status.NOT_FOUND).build(); }
  • A A exceção propaga sem tratamento e interrompe a aplicação.
  • B É capturada e a API de loans responde 404 NOT FOUND.
  • C É capturada e a API responde 500 INTERNAL SERVER ERROR.

9 Por que listBooks() retorna List<Book> diretamente, e não um Response, ao contrário de getBook(id)?Response

  • B É um erro de implementação: todo método deveria retornar Response.
  • C Porque List não pode ser serializado para JSON.

  • C Um contador de requisições para fins de métricas.

  • B Permitir que os dois microsserviços rodem simultaneamente na mesma máquina, sem conflito de porta.
  • C Definir a porta de conexão com o banco de dados.

Gabarito comentado

1@Path define a URI base do recursoA
✓
A —

Correta. @Path no nível da classe mapeia o recurso a um segmento de URI (aqui, /books); os métodos combinam esse caminho com o seu próprio @Path, se houver.

✕
B —

O verbo HTTP é definido por anotações próprias (@GET, @POST, @PUT...), não por @Path.

✕
C —

Registrar um cliente REST é papel de @RegisterRestClient, usado do lado de quem consome, não de quem expõe o recurso.

✕
D —

O formato de serialização é controlado por @Produces/@Consumes, não por @Path.

2Records como modeloA
✓
A —

Correta. Records existem justamente para modelar dados imutáveis com menos código: o compilador gera construtor canônico, acessores (id(), title()...), equals, hashCode e toString.

✕
B —

Records não suportam herança de outras classes (só podem implementar interfaces); o contrário do que a alternativa afirma.

✕
C —

Não existe essa exigência; um recurso @Path pode usar qualquer POJO como modelo, record ou não.

✕
D —

Records descrevem dados; as anotações JAX-RS continuam necessárias para expor endpoints.

3Código HTTP para conflito de estadoC
✕
A —

200 indicaria sucesso na operação de empréstimo, o que não ocorre quando o livro já está emprestado.

✕
B —

404 é usado quando o livro não existe (book == null), caso diferente e tratado antes no mesmo método.

✓
C —

Correta. O livro existe, mas o estado atual do recurso conflita com a operação solicitada — esse é exatamente o uso semântico de 409 CONFLICT.

✕
D —

400 indicaria uma requisição malformada; aqui a requisição é válida, apenas o estado do recurso impede a ação.

4@RegisterRestClientA
✓
A —

Correta. O MicroProfile REST Client gera em tempo de execução uma implementação de IBookCatalog que traduz as chamadas de método em requisições HTTP para o serviço catalog.

✕
B —

Quem implementa o servidor do catalog é CatalogResource, em outro módulo; IBookCatalog vive em loans e é só o contrato do cliente.

✕
C —

Os métodos declaram @Produces(MediaType.APPLICATION_JSON); não há serialização XML envolvida.

✕
D —

IBookCatalog não expõe rotas — ela consome rotas de outro serviço.

5Injeção do cliente RESTB
✕
A —

IBookCatalog é uma interface; não é instanciada com new, e sim provida pelo container CDI.

✓
B —

Correta. A combinação @Inject (CDI) com @RestClient (MicroProfile) instrui o Quarkus a injetar a implementação gerada do cliente REST.

✕
C —

@Autowired é uma anotação do Spring, não usada em projetos Quarkus/Jakarta EE.

✕
D —

@Produces serve para expor um bean via método produtor, não para injetar um campo.

6baseUri: anotação x application.propertiesB
✕
A —

Fixar a URL no código não facilita testes — pelo contrário, impede trocar o endereço entre ambientes (dev, teste, produção) sem recompilar.

✓
B —

Correta. O material da disciplina recomenda configurar a URL do cliente via application.properties, com a chave {pacote.Classe}/mp-rest/url — por exemplo, edu.ifrs.client.IBookCatalog/mp-rest/url=http://localhost:9080/books. O baseUri fixo na anotação funciona, mas é a exceção, não o padrão ensinado.

✕
C —

Variáveis de ambiente são uma opção válida em produção, mas não é o mecanismo apresentado no material do curso para este ponto.

✕
D —

Usar sempre localhost quebraria a comunicação entre serviços implantados em máquinas ou contêineres diferentes.

7Tratamento de WebApplicationExceptionB
✕
A —

O bloco try/catch captura exatamente essa exceção; ela não propaga sem tratamento.

✓
B —

Correta. O catch intercepta a falha (o cliente REST lança WebApplicationException quando recebe 404 do catalog) e converte a resposta de loans em 404 NOT FOUND.

✕
C —

O código devolve explicitamente Status.NOT_FOUND, não 500.

✕
D —

A exceção não é ignorada: o método retorna imediatamente uma resposta de erro, interrompendo o fluxo de criação do empréstimo.

8Verbo HTTP para marcar empréstimoC
✕
A —

@POST é usado para criar recursos novos (como um livro ou um empréstimo), não para atualizar o estado de um existente.

✕
B —

@PATCH não é usado em nenhum lugar deste projeto.

✓
C —

Correta. Tanto CatalogResource.loanBook (@PUT @Path("/{id}/loan")) quanto IBookCatalog.markAsLoaned usam @PUT, consistente com a ideia de atualizar o estado de um recurso existente.

✕
D —

@DELETE removeria o recurso; marcar como emprestado é uma atualização, não uma remoção.

9Retorno direto do tipo x ResponseA
✓
A —

Correta. JAX-RS aceita que o método retorne diretamente a entidade; nesse caso o runtime monta a resposta com status 200 OK. Response só é necessário quando o método precisa escolher o status dinamicamente, como em getBook (200 ou 404).

✕
B —

Não é um erro: é uma forma válida e comum do JAX-RS, usada quando não há necessidade de variar o status HTTP.

✕
C —

List é serializável para JSON normalmente pelo provider JSON do Quarkus, desde que os elementos também sejam serializáveis (como o record Book).

✕
D —

@GET permite retornar Response normalmente — é exatamente o que getBook(id) faz.

10AtomicLong idGeneratorB
✕
A —

Sessão HTTP é um conceito à parte; o campo não tem relação com identificação de sessão de cliente.

✓
B —

Correta. Como os dados ficam em um ConcurrentHashMap em memória (sem banco de dados), o AtomicLong gera IDs únicos e crescentes de forma segura mesmo sob acesso concorrente, simulando uma chave primária autoincremento.

✕
C —

Não há nenhuma integração com métricas (isso seria tema do módulo de Metrics, não implementado aqui).

✕
D —

O valor é um contador incremental (getAndIncrement()), não um timestamp.

11Portas distintas por serviçoB
✕
A —

A propriedade quarkus.http.port tem efeito direto: sobrescreve a porta padrão (8080) da aplicação Quarkus.

✓
B —

Correta. Em uma arquitetura de microsserviços, cada serviço roda como um processo HTTP independente; portas distintas (9080 e 9081) evitam que um processo tente ocupar a porta já usada pelo outro na mesma máquina.

✕
C —

Não há banco de dados configurado neste projeto; os dados ficam em memória.

✕
D —

Não há configuração de HTTPS/TLS nas propriedades mostradas.

12Serviço remoto indisponívelB
✕
A —

Esse comportamento de fallback só existiria com Fault Tolerance (@Fallback), tema de um módulo posterior — não implementado neste projeto.

✓
B —

Correta. Sem tratamento de resiliência, uma falha de conexão do REST Client (serviço fora do ar) resulta em exceção propagada, refletindo em erro na chamada de loans.

✕
C —

O MicroProfile REST Client básico não faz cache automático de respostas.

✕
D —

Uma falha de chamada remota não reinicia a aplicação chamadora.
